# B101 - Deduplicated Scene thumbnail overwrites shared source art

**Severity:** Critical
**Status:** Fixed (v1.15.10)
**Found:** 2026-08-25 during the full *Tomb of Annihilation* v1.15.9 test conversion
**Component:** `src/entities/scenes.py` (`Scene.createThumbnail`)
**Related:** B056, B097

## Defect

B097 correctly stores an acquired asset under SHA-256(body), but Scene conversion then calls
`createThumbnail()` on the returned path. The function resizes the image to 300 x 100 and replaces
that file in place.

Under `--dedup-assets`, the path is package-wide and may be referenced by a map, Tile, Actor,
Journal, or another Scene. Replacing it corrupts every shared reference and leaves a file whose
bytes no longer match its content-address name. The next equal-body acquisition detects this as:

```text
Asset content-hash path collision: .../assets/90b934879097...56031dc5d.png
```

The failed ToA source-candidate run measured the named path at 67,367 bytes with actual SHA-256
`D3B948002253FEE769F0FD2B7E8034EDEF8992A1CC6BA125A56A9A2FE5EBB2F2`; the filename claims
`90B934879097AE366B5F5008C07D034605C47DC0558E181886E27BF56031DC5D`.

## Cause

`copyZipFile()` returns the package-wide content-addressed source path. `createThumbnail()` was
written for the old per-reference layout and unconditionally used `os.replace()` to overwrite that
path with generated thumbnail bytes. B097 changed ownership of the path but did not change this
post-write mutation.

## Required handling

- Never mutate an acquired content-addressed body.
- In dedup mode, render the thumbnail separately and place the generated bytes through the same
  content-addressed writer.
- Update the Scene thumbnail reference to the generated thumbnail's exact path.
- Keep established in-place behavior when deduplication is disabled.
- Prove the source path remains byte-identical, the thumbnail path hashes to its own bytes, and the
  Scene reference uses that new path.
- Re-run a full production-sized conversion; unit tests alone did not expose this lifecycle defect.

## Candidate resolution

`createThumbnail()` now accepts the intended thumbnail destination. In dedup mode it renders into
memory, stores those generated bytes through `_storeAssetContent()`, and returns the new physical
and Foundry paths. The Scene updates its thumbnail reference to that returned path. Non-dedup mode
retains the existing in-place conversion.

The focused shared-body regression passes 1/1 and the neighboring thumbnail/asset suite passes
77/77. The combined B099/B101 Python 3.8 suite passes 965/965.

The repaired full ToA source-candidate conversion completes with exit 0 after the separately
recorded Bone Naga source cleanup and declared Tokenizer dependency. Its sealed Gate A result was
36 pass / 1 fail / 4 skipped: G41 passed, while G12 failed on two duplicate Dao spell rows caused
by source-input ambiguity unrelated to B101. After deterministic source cleanup v2 removed those

G41, and G42. Independent logical verification of the first candidate measures 1,910 assets /
1,303,201,729 bytes with zero duplicate bodies and zero root content-hash mismatches. The candidate
